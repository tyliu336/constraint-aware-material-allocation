# 产品边界

## 产品负责什么

- 导入版本化材料库存和 Slot 要求；
- 对字段、单位、ID、证据和状态做确定性校验；
- 用硬规则产生 `pass / fail / not_evaluable`；
- 在合法候选中寻找完整方案并计算软偏好；
- 保存数据、规则、方案、工具调用和人工审批证据；
- 让受控 Agent 理解偏好、调用业务工具和解释已有证据。

## 产品不负责什么

- 木材结构分级、结构安全认证或工程师签章；
- 把扫描、图像或自然语言自动提升为安全事实；
- 允许 LLM 降低或覆盖正式硬约束；
- 在没有批准时修改库存或执行加工；
- 把旧论文实验状态迁入产品核心。

## TreeTrace 数据和界面图

TreeTrace 原始结构化数据在首个案例中作为只读材料来源。它通过独立 Adapter 进入产品，并保留来源 ID、原始字段、单位转换、文件 hash 和行级 hash。

TreeTrace 相关界面图、截图或材料图像可以加入，但用途必须分开：

| 资源 | 允许用途 | 禁止用途 |
|---|---|---|
| 原始数据表 | 材料 observed 字段和可追溯导入 | 回写或覆盖原文件 |
| 数据集界面截图 | 来源说明、演示素材、文档和 UI 视觉回归参考 | 作为结构化库存真源 |
| 单件材料图像/扫描图 | 人工查看和外观软偏好分析 | 单独证明结构合格 |
| 后验破坏试验结果 | 离线验证与研究分析 | 在分配前作为模型可见信息 |

图片必须通过 `image_manifest_ref` 或同类稳定引用关联材料，并保存来源、许可、文件 hash、拍摄/生成时间和视角。没有明确材料对应关系的界面截图只能用于说明，不进入规则判决。

## Agent 边界

产品包含受控 Agent，但 Agent 不拥有硬规则裁决权。领域合同先于模型调用建立；语义理解、工具调用和有界编排只能在这些合同之上运行。只有质量和运行数据证明拆分带来收益时，才把逻辑角色部署为多个模型驱动 Agent。
