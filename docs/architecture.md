# 系统架构

## 主要数据流

```text
浏览器 / MCP 客户端
        │
        ▼
FastAPI 路由与身份校验
        │
        ▼
WorkflowService / QueryService
        │
        ├── 自然语言解释器（OpenAI）
        ├── 确定性规则引擎
        ├── 候选图与完整匹配
        └── 软偏好排序
        │
        ▼
Unit of Work / Repository
        │
        ▼
SQLite 或 PostgreSQL
```

## 职责边界

### 领域层

`domain/` 定义材料、构件、规则结果、方案状态和证据字段。Pydantic 模型在数据进入业务逻辑前检查 ID、单位、枚举和值域。

### 规则层

`rules/` 对单个材料—构件组合执行尺寸、结构评估、强度等级和缺陷规则。每条规则返回 `pass`、`fail` 或 `not_evaluable`，并保留实际值、要求值和来源引用。

### 求解层

`solver/` 把所有组合构造成二分图。已验证图只包含 `pass` 边，乐观图还包含 `not_evaluable` 边。系统分别计算完整匹配，以区分“已经证明可行”“补齐记录后可能可行”和“已知条件下不可行”。

### 应用层

`application/` 组合授权、版本快照、求解、方案保存、人工决定、库存预留和受控工具。写操作通过 Unit of Work 提交，失败时回滚。

### 接口层

`api/` 暴露 HTTP 接口并提供网页资源。Bearer token 映射到用户、项目和角色；应用服务会再次检查权限，不能只依赖页面隐藏按钮。

### 持久化层

`persistence/` 使用 SQLAlchemy 实现 Repository 和事务。开发环境默认使用 SQLite，部署配置使用 PostgreSQL。Alembic 管理数据库结构。

## LLM 边界

自然语言模型处理模糊表达，但输出必须满足固定 Schema。它可以选择受支持的软偏好和权重，不能：

- 修改材料原始值；
- 把未知记录改成通过；
- 降低结构硬条件；
- 直接批准方案；
- 直接预留库存。

系统另有受预算限制的 Agent Runtime，工具由白名单提供，并记录调用和终止原因。

## 一致性与审计

- 库存、需求和方案均使用版本化快照；
- 输入内容、候选矩阵和方案具有稳定哈希；
- 保存方案时重新运行硬规则；
- 审批与库存预留是不同操作；
- PostgreSQL 条件唯一索引防止同一材料被并发预留；
- 导出文件是复核资料，不是加工指令。
